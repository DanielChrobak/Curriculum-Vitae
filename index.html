Behind the project +

The problem

Make a Windows desktop interactive in a browser while coordinating capture, GPU encoding, network delivery, decoding, audio, and input. Display changes, decoder backlogs, and interrupted connections need recovery across the native and browser components.

The implementation

DXGI/WGC capture, NVIDIA NVENC, AMD AMF, Intel QSV, and Media Foundation encoding paths; MsQuic/WebTransport delivery; WebCodecs decoding and WebGPU/WebGL rendering. Adaptive bitrate, frame pacing, multi-monitor controls, account permissions, and Windows service packaging support the complete application.

Source repository is private. Codec, HDR, and hardware paths depend on host and browser capabilities. Diagrams illustrate architecture; they do not represent a live session or measured end-to-end latency.

ONE HOST / MULTIPLE GUESTSGPU-PV
Behind the project +

The problem

GPU-enabled virtual machines require more than assigning a device. Guest drivers need to match the host, and changes need a reliable recovery path.

The implementation

Device discovery, per-adapter assignment, and driver-package planning for NVIDIA, AMD, and Intel. SHA-256 checks, staged copies, and a recovery journal protect guest driver updates. Desktop, console, and headless workflows share the same PowerShell tooling.

Support depends on the GPU, host driver, and guest Windows version. Built on the community GPU-PV method; the repository documents prerequisites and community foundations.
